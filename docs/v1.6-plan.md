# bettermemory v1.6 plan

_Date drafted: 2026-05-16. Author: Mattias + Claude planning pass._

> **Status: shipped as v2.0.0 on 2026-05-16.** Nine of the ten tiered features below (T1.1, T1.2, T1.3, T2.1, T2.2, T2.3, T3.1, T4.1, T4.3) landed in one major release rather than the planned 1.6→1.7→1.8 sequence. T3.2 (embedding cache pruning) and T4.2 (team scopes with ACLs) remain unshipped. See the [2.0.0 entry in `CHANGELOG.md`](../CHANGELOG.md) for the as-shipped detail. This document is preserved as the planning record — the competitive snapshot and design rationale are still the reference for why each feature exists.

The goal: ship 1.6 (and 1.7, 1.8 in sequence) so bettermemory becomes the unambiguous best-in-class persistent-memory system for LLM agents — beating Anthropic's first-party memory tool, mem0, Letta, Zep, Cognee, and the OSS MCP field.

---

## Where v1.5 stands

17 MCP tools, fsync-hardened, ~790 tests, MIT, plain-markdown storage. Three durable moats no competitor matches:

1. **First-class verification with structured attestation** — `memory_verify(verified_paths=[...], verified_commits=..., verified_versions=...)`. Persistently records *what* was spot-checked, not just *that* something was.
2. **Opt-in retrieval as a contract** — model searches when justified, never auto-loads. The structural answer to mem0's 97.8%-junk problem.
3. **Pending-confirm tier for `category="user-inference"`** — claims about the user always require user veto before commit. Failure mode "AI misattributed my preference" is unsolved everywhere else.

Plus a `staleness_verdict` rollup on every retrieval (calendar + filesystem + commit drift folded into one field), tombstone-aware dedup, scope_mismatch gating, auto-`record_use` lifecycle, and worktree-aware auto-scoping.

## Competitive snapshot (May 2026)

| System | Storage | Retrieval | Pitch | Critical weakness |
|---|---|---|---|---|
| **Anthropic Memory Tool** | files (host-implemented) | none — list+read only | "no search, Claude self-organizes via filenames" | no verification/curation/provenance; security delegated to host (MCP CVE pattern) |
| **mem0** | vector + optional graph | semantic | "auto-extracted, token-efficient" | **97.8% junk rate** in production audit ([issue #4573](https://github.com/mem0ai/mem0/issues/4573)); feedback-loop contamination |
| **Letta** (MemGPT) | core/recall/archival tiers | tool-driven | "sleep-time compute, dual-agent" | heavy topology; context-window growth complaints |
| **Zep / Graphiti** | temporal knowledge graph | BM25 + vector + graph | "bi-temporal: `t_valid` + `t_created`" | async ingest delay; LOCOMO benchmark disputed |
| **Cognee** | graph + vector + SQL | hybrid + ontology | "OWL-class entity validation" | no published benchmarks; pre-1.0 (v1.1.0.dev1) |
| **Memori** | SQL (BYO Postgres/MySQL/SQLite) | structured queries | "anti-vector, 81.95% LOCOMO @ 1.3K tokens" | young project; pipeline details thin |
| **mcp-memory-service** | sqlite-vec / Milvus / hybrid | BM25 + vector RRF | "typed edges, autonomous consolidation" | inconsistent across backends |
| **Engram** | Go + SQLite FTS5 | full-text + semantic | "What/Why/Where/Learned schema" | small community; Go stack |

Plus academic systems: **MemoryOS** ([arxiv 2506.06326](https://arxiv.org/abs/2506.06326), three-tier OS-style heat eviction), **A-MEM** ([arxiv 2502.12110](https://arxiv.org/abs/2502.12110), Zettelkasten with memory evolution), **HaluMem** ([repo](https://github.com/MemTensor/HaluMem), first operation-level *write-time* hallucination benchmark).

## The 1.6 thesis

The field is splitting three ways:
- **Graph-heavy** (Zep, Cognee, mcp-memory-service)
- **Vector-heavy** (mem0)
- **File-heavy** (Anthropic)

Each has a structural weakness — graphs add infra burden, vectors hallucinate at write time, files have zero curation. bettermemory's bet is a fourth path: **a small, file-backed system with strong write-time gates, structured verification, and an explicit retrieval contract.**

1.6 should triple-down on what only bettermemory does — *verification-grade memory* — and close the two real gaps competitors will weaponize: no hybrid retrieval, no sleep-time consolidation.

## 1.6 feature plan, ranked

### Tier 1 — Must-do (the rebuttal to "but mem0 has X")

#### T1.1 — Provenance/citation on retrieval

When a retrieved memory shapes a response, emit a structured citation: `{memory_id, claim_excerpt, last_verified_at, verified_paths}`.

Surface via either:
- a new `memory_cite(memory_id, claim)` tool, or
- a field on `memory_record_use(outcome="applied", claim_excerpt=...)`.

Closes the mem0 hallucination gap. OpenAI's "memory sources" UI is the only competitor with a primitive version of this, and it's read-only / non-programmable.

#### T1.2 — Hybrid retrieval: BM25 + Jaccard + optional vector via RRF

Jaccard is fine for keyword-heavy queries but loses on paraphrase. Add BM25 on the same tokenizer (zero new deps), reciprocal-rank-fusion with semantic when extras are installed. Files remain canonical.

Removes the "they have search, you have keyword" rebuttal without changing the storage model.

#### T1.3 — Write-time hallucination gate (`groundedness_check`)

`memory_write(groundedness_check=True, source_transcript=...)`: compare the proposed body's claims against the recent turns. Claims without grounding return `status: "ungrounded"` with the unsupported phrases listed — same family as `transient_warning` / `scope_mismatch` / `duplicate`.

**HaluMem made operational; nobody else does this.**

### Tier 2 — Differentiator (sleep-time + graph-lite, without the infra)

#### T2.1 — `bettermemory consolidate` CLI

Closes the Letta gap without dual-agent topology. One command that:

- semantic-similarity dedups near-duplicates (extras already in place)
- demotes never-applied memories to `category=ambient`
- ages out cold scopes (suggest, don't auto-delete)
- resolves scope-typo pairs from the Levenshtein detector
- dry-runs by default, `--apply` to commit

#### T2.2 — Typed inter-memory links

Add `links: [{type: "supersedes"|"contradicts"|"extends"|"depends_on", target_id, note}]` to the memory record. In `memory_search`, optionally suppress `supersedes`d results; flag mutual contradictions.

Adopted from mcp-memory-service's typed-edges idea but plumbed into retrieval, not just storage.

#### T2.3 — Negative-results memory

When `memory_record_use(outcome="ignored"|"contradicted")` fires, subsequent searches for similar tokens annotate matching results with "this was rejected on $date" so the model doesn't keep re-suggesting the same junk.

### Tier 3 — Scale (remove the 5-10K linear-scan ceiling)

#### T3.1 — SQLite FTS5 inverted index, files canonical

Index is a derived cache; markdown remains source of truth. Rebuilt by `bettermemory reindex`. Removes the `load_all` bottleneck without losing grepability / git-trackability.

#### T3.2 — Embedding cache pruning

Auto-prune entries whose memory was removed or whose body changed.

### Tier 4 — Network effect (homelab-fit, plays existing strengths)

#### T4.1 — `bettermemory sync push/pull` between hosts

restic-style or git-style replication of the memory store. Three ZimaBoards and a Mac — memory should follow the user. Per-host origin tracking already exists.

#### T4.2 — Team scopes with simple ACLs

`team:<name>` namespace where multiple agents read but one writes (or RBAC via `.acl`). The credible answer to "cross-agent shared memory" that G-Memory only studies academically.

#### T4.3 — Local web UI: `bettermemory ui`

Local-only FastAPI + tiny SPA. Browse, verify, view audit timelines. Optional; CLI remains primary. Killer use-case is the curation surfaces (`dead_weight`, `contradictions`, `never_verified`) where a UI beats a tool call.

## What to cut

- **No graph DB.** Cognee/Zep/mcp-memory-service carry that weight; our edge is being not-that. T2.2 (typed links) is graph-lite without the infra.
- **No auto-extraction from conversation.** That's mem0's whole pitch and the source of its 97.8% junk problem. The opt-in retrieval contract loses meaning if you bolt on auto-write.
- **No managed cloud.** Don't compete on infra; compete on quality.

---

## Suggested release sequencing

- **1.6.0** — T1.1 (provenance) + T1.2 (BM25/RRF) + T2.1 (consolidate). _"Recall becomes more accurate and more accountable."_
- **1.7.0** — T1.3 (write-time gate) + T2.2 (typed links) + T2.3 (negative results). _"Writes get safer, retrieval gets smarter."_
- **1.8.0** — T3.1 (FTS5 index) + T4.1 (sync) + T4.3 (web UI). _"Scales out — bigger corpora, across machines."_
