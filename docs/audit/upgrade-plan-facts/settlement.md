## 1. `session.py` use-token lifecycle

- **Creation**: `SessionState.issue_use_tokens(memory_ids)` — `src/bettermemory/session.py:303-323`. Mints `"use_" + secrets.token_hex(8)` per id, stores `PendingUseToken(token, memory_id, issued_at=time.time(), issued_at_turn=turn_counter)` keyed **by memory_id** (not token) in `pending_use_tokens` (session.py:137). Call sites: `src/bettermemory/handlers/show.py:120` (single id) and `src/bettermemory/handlers/search.py:1041` → `_attach_use_tokens` (`src/bettermemory/handlers/_shared.py:488-505`, bulk mint, injects `use_token` into each hit dict). Re-issue for a pending id **replaces** the old token.
- **Constants**: `_PENDING_USE_TOKEN_TTL_SECONDS = 30*60` (session.py:62), `DEFAULT_USE_TOKEN_TTL_TURNS = 2` (session.py:72), `AUTO_COMMIT_MIN_AGE_SECONDS = 600.0` (session.py:84). The 600s floor is deliberately NOT imported from audit.py; equality with `audit.ATTRIBUTION_LOOKBACK_SECONDS` (=600, `src/bettermemory/audit.py:147`) is cross-pinned by `tests/test_telemetry_v2.py:626` (`assert AUTO_COMMIT_MIN_AGE_SECONDS == float(ATTRIBUTION_LOOKBACK_SECONDS)`).
- **The [600s,1800s) in-process settle window**: `consume_old_tokens` (session.py:325-374) pops ids where `issued_at_turn <= turn_counter - ttl_turns` (default 2 handler entries, session.py:364) **AND** `issued_at <= now - 600` (session.py:365-370). Eviction: `_evict_expired_use_tokens` (session.py:385-393) deletes tokens with `issued_at < now - 1800` — **bare `del`, no return value, no stash, no event**. Ordering: `advance_turn` (session.py:287-301) bumps the counter, then calls `_evict_expired_use_tokens()` (line 299) then `_evict_expired()` (pending writes, line 300). `consume_old_tokens` runs afterwards, from `_advance_turn` in `src/bettermemory/handlers/_shared.py:298`. Net: a token consumed at a handler entry with wall-age in [600,1800) auto-commits `applied`; one whose first post-600s handler entry lands at age ≥1800s is silently evicted first and never settles. No handler call at all → the token dies with the process (in-memory only).
- **Where an eviction event would be emitted**: `SessionState` has no recorder (deliberate — session.py:78-79 "session.py stays dependency-free of the audit stack"). The existing template is the pending-write pair: `_evict_expired` stashes into `_expired_pending` (session.py:238-264), drained by `pop_recently_expired()` (session.py:266-279), and the **handler-side** `_drain_pending_expired(state, recorder)` emits one `pending_expired` event per drop (`src/bettermemory/handlers/_shared.py:219-251`), called from `_advance_turn` (`_shared.py:293`). An analogous `use_token_expired` needs: stash in `_evict_expired_use_tokens`, a drain method, and emission inside `_advance_turn` (`_shared.py:254-306`), which already holds the recorder and emits the auto-commit event at `_shared.py:300-306` (`kind="use", outcome="applied", auto=True, attribution="auto"`).
- **Other silent-drop paths** (no event possible today): `SessionState.reset()` clears `pending_use_tokens` (session.py:405); `SessionRegistry.for_request` LRU-evicts whole states (`popitem(last=False)`, session.py:508-510); process exit.
- Before consume runs, `_advance_turn` purges tokens already settled in the log: `_already_recorded_pending_ids` (`_shared.py:355-479`) scans `iter_events(recorder.root)` (**active shards only, not window-aware** — `_shared.py:431`) backwards for `kind=="use"` events (any outcome, `_shared.py:448`) whose session is in `{recorder.session_id} ∪ stop-hook transcript ids ∪ extra` and whose `ts >= token.issued_at`.

## PLAN HAZARDS

1. **New event kind vs new `use` outcome have disjoint blast radii.** Both dedup scans that prevent double-settlement filter `kind == "use"` with **no outcome check** (`_shared.py:448` + id-add at 462-478; `hook.py:898-906`). Emitting `use_token_expired` as a **new kind** means the hook's `_pending_retrievals` still sees the id as pending (if a retrieval is inside the 600s lookback) and can attribute it again, and `_already_recorded_pending_ids` won't purge on it. Emitting it as `kind="use", outcome="expired"` dedups for free but: `_handle_use` bumps `last_used_at` for **any** outcome (health.py:1239-1242), `_USE_OUTCOMES` (`_shared.py:49-61`) doesn't include it (record_use would reject it, fine — but doc/test parity in `tests/test_server_record_use.py` may pin the set), and every `use` consumer's else-branch must be audited. Pick one deliberately; don't mix.

2. **The AST kind-parity test is a tripwire in both directions** (tests/test_eval.py:1725-1804). Literal kind at the call site → must be added to exactly one roster; kind via module constant → must be added to **neither** (stale-entry assert). And the in-session/admin classification (`_IN_SESSION_SIDE_EFFECT_KINDS`) decides whether `is_admin_recorded_event` hides the event from doctor's census — an eviction event recorded by the live server is in-session; misclassifying it makes doctor drop real session activity.

3. **A SessionStart hook that writes ANY event under a fresh session id manufactures phantom sessions.** `doctor._check_audit_turn_cadence` counts every non-admin session (doctor.py:985-987); a throwaway `SessionState()` id (the consolidate-CLI pattern) with zero `turn_audited` pushes `n_sessions` toward the ≥2 warn threshold on healthy stores. Reuse the SessionStart payload's `session_id` (the same transcript id the Stop hook will later stamp `turn_audited` under) or stamp `attribution="cli_*"`.

4. **`_latest_in_process_session` skips only `triggered_from == "stop_hook"`** (hook.py:719). Any event a SessionStart process records without that exact tag becomes "the latest in-process event" and hijacks the server-session anchor (disabled-scope replay, retrieval shield, attribution session) until the real server's next tool call. The tag vocabulary is a closed set (`audit.py:256`) enforced only inside `turn_audited_fields`/`search_miss_fields` — other event shapes can carry any value, but a new value (`"session_start_hook"`) is **not** skipped by the anchor walk at hook.py:719 unless that comparison is widened. Widening it changes settled semantics for every existing consumer of the anchor.

5. **SessionStart stdout is injected verbatim into context.** The current Stop command prints a JSON report to stdout unless `--quiet` (hook.py:993-994). A SessionStart command reusing this CLI style must print exactly the intended context and nothing else — `uvx` cold-start noise goes to stderr (safe), but any stray stdout (e.g. the audit JSON) becomes context. Also `uvx` cold-cache latency: Stop's timeout is 30s; SessionStart default is 600s — set an explicit small timeout, and keep `|| true` (older PyPI versions won't have a new subcommand; the hooks.json `$schema-comment` at plugin/hooks/hooks.json:2 documents this exact rationale).

6. **There is no scope-overview CLI.** `memory_scope_overview` is an async MCP handler needing `ToolHandlers` deps (`handlers/scope_overview.py:93-97`); the subcommand roster (`cli/__init__.py:100-118`) has no equivalent. A SessionStart hook needs a new subcommand (order/help pinned by `tests/test_cli_smoke.py:56` `test_help_lists_all_subcommands`, dispatch table `cli/__init__.py:140-190`), and the handler's session-dependent fields (`disabled_scopes`, `pending_writes` from `SessionState`; `conflicts` from `ConflictQueue`; delta anchored on `deps.recorder.session_id` at scope_overview.py:235-238) don't transfer to a fresh process: a CLI run has empty session state and its own recorder id, so `find_prior_session_boundary` computed there anchors differently than the server's own call would. Also note the handler **records a `scope_overview` event** (scope_overview.py:307-319) — combined with hazards 3+4, a naive CLI port that keeps the `.record` call pollutes the census and the anchor. And it calls `_advance_turn` (line 101), which in a fresh process is harmless but in any shared-state refactor would fire auto-commits.

7. **A "settle prior-session tokens at next session start" pass that emits `applied` events poisons the endorsement telemetry.** Every published metric treats `applied` as evidence: auto-applied feeds `cold_endorsement_memories` (health.py:1690-1717) and blocks `dead_weight`'s `applied_count > 0` gate (health.py:173), and `endorsement_boost` ranking reads applied tallies. Prior-session leftovers are precisely retrievals with **no** evidence of use; settling them as `applied, auto=True` converts dead-weight signal into cold-endorsement signal wholesale. The grace machinery (`_ENDORSEMENT_GRACE_DAYS`, health.py:84-92) exists because these produce no event — an "expired/unsettled" record must be a non-`applied` shape or the dead-weight/demotion pipeline silently changes meaning.

8. **Coverage-gate threading is three-way.** Any new parameter to `_is_dead_weight` must be threaded through all three call sites (health.py:1541, health.py:2720, consolidate.py:843) and their three **independent** event walks (accumulator, curation_counts inline loop, find_demotion_candidates loop) — `tests/test_health.py` pins numerical agreement between `curation_counts` and `compute_health` (docstring contract health.py:2528-2534), so a gate added to one path fails those tests, and a gate added only to the report (not the demotion pass) recreates the exact reported-but-undrained divergence the shared predicate was built to kill (health.py:71-82).

9. **eval/health split-by-attribution is back-compat-sensitive.** Legacy events lack `attribution`; the documented fallback (model when `auto` false) is currently implicit because rollups branch on `auto` alone (eval.py:55-57, 622; health.py:1206-1217). A split surface that reads `attribution` directly must fold `attribution=None ∧ auto≠True` into "model" and keep the strict `is True` auto test (`legacy auto=1`/`"true"` read as explicit — eval.py:616-621), or historical stores shift buckets. Also `attribution="cli_*"` rows (acknowledge-debt) are genuine endorsements that count toward `applied_total`/`endorsement_rate` (eval.py:2469-2473) — an attribution-tier split must not reclassify them as a fourth tier that changes published rates.

10. **`memory_scope_overview` cost is not hook-cheap.** The handler materialises `iter_all_events` (every archive, gzip decode — scope_overview.py:165) plus `store.load_all()` twice-run `curation_counts`. On the dogfood store this is the same scale as `compute_health` (comment scope_overview.py:160-164). Inside a SessionStart hook this cost lands on every session/resume/clear/compact — with `matcher` unset it fires on **all five** matchers; scope it (`startup`, probably `resume`) explicitly.

11. **`_evict_expired_use_tokens` runs before `consume_old_tokens`, from a different module.** The eviction happens inside `SessionState.advance_turn` (session.py:299) but the auto-commit and any event emission happen in `handlers/_shared._advance_turn` (`_shared.py:292-306`).
