# Retrieval spend + episodes-primary — HEAD facts (95af021, v3.30.0)

## 1. Snippets — blind head-of-body truncation

**Current mechanics.** `snippet_for(body, max_chars=200)` at `src/bettermemory/models.py:874-885`: `body.strip()`, return whole if ≤200 chars, else `_truncate_at_word` (`models.py:888-904` — back off to last whitespace/newline/tab within 40 chars of the cut, `rstrip(" ,;:.-")`, append `"..."`). The query plays no role; it is always the head of the body.

**Search-hit call site.** `search.py:1842` inside `_build_hit` (`src/bettermemory/search.py:1816-1857`). `_build_hit` is invoked at `search.py:2409-2412` (post-rank, post-trim `scored[:max_results]`) and `search.py:2252` (browse mode). Serialized to the wire at `src/bettermemory/_response.py:147` (`hit_to_dict`). Crucially, `_build_hit` **already receives `matched: list[str]`** (the query tokens that hit, per-hit) and ignores it for the snippet.

**Other consumers of `snippet_for`** (changing the function globally changes these): `consolidate.py:576,578,645,647,726,728,871` (all `max_chars=100`, dedup/duplicate summaries); `audit.py:893` reuses `hit.snippet` as the retained silent-miss trace (`audit.py:269-271` — "id + snippet is enough"). `SimilarHit` dedup hits also use it (`search.py:2785,2803`).

**FTS5-preprocessed wrinkle — CONFIRMED.** The FTS table indexes `body_fts`/`scopes_fts` only (`src/bettermemory/index.py:218-222`), which carry `search.fts_index_text` output (`index.py:210-217`). `fts_index_text` = `" ".join(_expand_kebab(tokenize(text)))` (`search.py:880-901`): lowercased, diacritic-folded, contraction-stripped, symbol-aliased (`C++`→`cpp`), `_`→`-`, plural-stemmed (`_stem_token`, `search.py:703-711`), CJK-bigrammed, kebab-part-expanded. Raw `body` sits on the content table but is **NOT indexed** (`index.py:215-217`). SQLite `snippet()`/`highlight()` over `memories_fts` would therefore return normalized token soup ("cooki polici docker-container docker container"), never prose. Any snippet improvement must be Python-side over the raw body.

**Python-side query-biased window — where the pieces are:**
- **Match terms:** per-hit `matched` from `score_memory` (`search.py:1588-1592`, returned via `_score_keyword`/`_score_bm25` at `1870/1920`, union-per-hit in hybrid at `search.py:2081,2093,2107`). These are **stemmed/folded** tokens, deduped.
- **Positions:** retained nowhere. `_tokenize_impl` uses `_TOKEN_RE.findall` (`search.py:777,793`) which drops spans. The workable design: `_TOKEN_RE.finditer` over the raw body, normalize each raw token individually (lower → `_stem_token`; `_kebab_parts` at `search.py:855-867` for compound membership), test membership against the `matched` set, pick the densest window, cut with `_truncate_at_word`-style word-boundary logic.
- **Cost:** run it only on emitted hits — `max_results` is handler-clamped to `MAX_SEARCH_RESULTS = 50` (`handlers/search.py:457,460-473`). One regex pass + per-token stem per hit body. Candidate-side tokenization already happens once per candidate (`search.py:2272`, `_memory_tokens` at `search.py:1115/1144`) but is positionless — do not try to reuse it for offsets.

## 2. Read-side diversification — post-RRF pipeline

**longmemeval finding, exactly** (`bench/longmemeval/README.md:288-316`): temporal-reasoning and multi-session are one failure mode — a top-k budget problem. Named cause: `score_memory`'s `0.5 + 0.5 * coverage` multiplier (`search.py:1672-1673`) can't be satisfied by either single-event session; and "There is no read-side diversification anywhere in search.py today: dedup runs at write time only" (`README.md:313-316`). ## 5. episode_handoff resolution logic

1. Clamp `max_episodes` (`:246-248`). Write floor for the **current** session before anything else (`:304-305`, `_maybe_write_session_floor` at `:799`, idempotent — skipped when the session already has any episode).
2. **Explicit `prior_session_id`:** respected verbatim, no walk (`:344`, `:568-596`); invalid id degrades to `episodes: []` (`:581-584`). Emit: floors filtered (`:600`), disabled-scope-filtered (`:608-609`), last `max_episodes` oldest-first (`:614`).
3. **Auto-resolve** (`:345-560`): caller worktree from `capture_origin` at entry (`:355`); walk `iter_all_events`, latest ts per `session != recorder.session_id`, plus per-session `worktree_root` from event stamps (`:371-386`); order most-recent-first, `(ts, sid)` tiebreak (`:392-396`). Per candidate:
   - `list_by_session`; `ValueError` → skip (`:427-433`).
   - **Zero-episode:** strict worktree match against event-stamped worktree; match → remember as fallback (+ note if immediately-prior), keep walking; mismatch/unknown-vs-named → skip (`:435-474`).
   - **Has episodes:** candidate matches if ANY episode's `origin.worktree_root` **strictly equals** the caller's (`:482-488`).
   - `visible_real` = non-floor AND not scope-disabled (`:497-502`); non-empty → **adopt, stop** (`:503-510`). Else floor-only → note+fallback; all-scope-hidden → silent rewind fallback (`:512-543`).
   - Walk exhausted (`for/else`, `:544-560`): fallback to floor-only/zero-episode sid, else scope-hidden sid.
4. Promotion-trace disambiguation only on the note path (`:642-646`; three-valued `promoted / staged-unresolved / none`, `:117-133`, `_episode_promoted_out_of_session` at `:856`).

**Worktree strictness:** `_worktrees_equal_strict` (`handlers/episode_handoff.py:992-1023`) — plain equality, `None` matches only `None`. Deliberately stricter than the permissive `origin.worktrees_match` that `episode_search`/`episode_patterns` use (either side None → True, linked-worktree and gone-from-disk pass-throughs). The two rules disagree on every pass-through case (`docs/api.md:303`).

## PLAN HAZARDS

1. **FTS5 `snippet()` is a dead end.** The index stores the preprocessed token stream (`index.py:210-222`); any plan step saying "use FTS5 snippet()/highlight()" yields stemmed token soup. The snippet must be computed Python-side over the raw body.
2. **Normalized-text offsets don't map to the raw body.** `_fold_ascii_safe` (contraction strip, symbol-alias subs) and NFKC are length-changing (`search.py:756-796`). Find positions with `_TOKEN_RE.finditer` on the raw text and normalize token-by-token; never fold the whole body and reuse its offsets.
3. **`matched` terms are stemmed/folded** ('cookies'→'cooki'); raw-token comparison requires re-stemming each raw token (`_stem_token`) and kebab handling in both directions (`_kebab_parts` for query compounds; index-side `_expand_kebab` means matched 'python' may exist only inside raw 'python-frontmatter').
4. **`snippet_for` is shared.** consolidate.py (6 sites, max_chars=100), audit trace (`audit.py:269-271, 893`), SimilarHit dedup hits (`search.py:2785,2803`). Scope a query-biased snippet to `_build_hit`'s call at `search.py:1842` (or a new function) unless changing those surfaces is intended.
5. **Tests pin snippet shape:** `tests/test_search.py:493-497` asserts total length ≤203 (`200 + "..."`); a mid-body window with a *leading* ellipsis breaks it unless the budget covers both ellipses. `tests/test_models_slug.py:125-145` pins newline-boundary backoff.
6. **Hits with `match_terms=[]` exist:** paraphrase-only semantic hits (`search.py:2035-2052`) and browse-mode hits (`search.py:2251-2253`). A window keyed on matched terms needs a head-of-body fallback for both.
7. **Diversification must land in `search.py`'s `search()` (between :2407 and :2409), not the handler.** The handler sees pre-trimmed hits; and both benches call `search.search` directly (`bench/retrieval/run.py:231`, `bench/longmemeval/run.py:270`), so a handler-side rescue is invisible to the bench that motivates it. It also propagates to the silent-miss audit probe by design (`resolve_search_pool` shared, `handlers/search.py:511-521`) — that's correct, but changed rankings change audit verdicts.
8. **longmemeval calls `search()` with `max_results=200`** — `clamp_search_width` is handler-only (`handlers/search.py:457-473`). A rescue/diversification pass must be sane at k=200, not just k=5.
9. **Per-hit cost budget:** `_build_hit` already pays `detect_path_drift` (≤8 stats, `search.py:1826-1836`). Snippet work is fine per emitted hit (≤50); never run it over the candidate pool.
10. **`--pad-to` does not measure the prefilter.** A real above-threshold arm needs a `Store` + built index + `load_search_candidates`/`resolve_search_pool`; `Store.write` indexes incrementally (`store.py:451`), and `BETTERMEMORY_INDEX_THRESHOLD` (read per search) is an alternative to padding. `INDEX_THRESHOLD` is duplicated at `bench/retrieval/run.py:91` and cross-pinned by `tests/test_bench_retrieval.py:169` — a production threshold change intentionally trips it.
11. **longmemeval per-question data is missing:** the runner emits `by_type` aggregates only; the +3.2 rescue table needed a re-run (`README.md:318-324`). Add per-question output before iterating on the re-ranker, or the improvement can't be verified against the published partial-rate baselines.
12. **DESC budget is actively policed.** HEAD commit 95af021 just trimmed `DESC_EPISODE_SEARCH`; `bench/toolcost` publishes the 4.84x context-cost loss. Substring pins in `tests/test_prompts.py` (`:262` `max_takeaway_bytes`, `:273` "most-recent", `:279+` worktree/disabled_scopes, `:301+` filter-language source checks) must survive any DESC edit.
13. **New MCP params must be mirrored in the `_handlers.py` facade** (`_handlers.py:8-21`; episode_search facade at `:490-503`) — FastMCP introspects the facade method signature; a param added only in `handlers/episode_search.py` never reaches the wire schema.
14. **Executor entering via `episode_handoff` from a different worktree gets nothing.** Strict equality (None matches only None) means a fresh clone, sibling worktree, or non-repo cwd resolves `prior_session_id=None` despite existing episodes. Cross-worktree reads require explicit `prior_session_id` or `episode_search(parent_session_id=/swarm_id=)` (never worktree-filtered).
15. **Episode walks are O(total episodes) and GC only fires on writes.** `episode_promote` by-id and the bare `episode_search`/`episode_patterns` walks read every file under `episodes/`; `prune_old_sessions` runs only in `episode_write` (`episode_write.py:161`) and the CLI — a read-only loop never GCs. Plans that raise episode write volume raise every walk's cost.
16. **Stale model docstring:** `models.py:650-652` claims episode scopes are "auto-defaulted from origin at the handler layer" — not implemented (`episode_write.py:152` passes `scopes or []`). Don't propagate that claim into the plan.
17. **Per-call `mode="semantic"` is not "works whenever the extra is installed"** — it errors under config keyword/bm25 without `semantic_dedup` even with the extra present (gate at `semantic_setup.py:111-137`). A plan describing defaults must state the hybrid-config-dependence.
18. **Query-dependent snippets change audit payloads.** `audit.py` retains `hit.snippet` as the miss-trace body substitute (`audit.py:269-271,893`); after the change the retained snippet varies per query — check tests pinning audit/`hit_to_dict` payload shapes before assuming byte-stability.
