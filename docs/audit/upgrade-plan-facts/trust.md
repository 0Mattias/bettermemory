## 1. Relative-citation regex (commit-drift anchoring) and the relative exclusion

- Regex: `_RELATIVE_CITATION_RE`, `src/bettermemory/verify.py:280-285`:
  ```python
  re.compile(
      r"(?<![\w/~.\\-])"
      r"((?:[A-Za-z_.][\w.\-]{0,63}/){0,12}"
      r"[A-Za-z_.][\w.\-]{0,63}\.[A-Za-z][A-Za-z0-9_]{1,7})"
      r"(?![\w/]|\.\w)"
  )
  ```
- Guards (design comment verify.py:230-279): lookbehind bars `[\w/~.\-\\]` so mid-path/mid-token/after-dash starts never re-match (`-` load-bearing, verify.py:263-270); ≤12 dir segments, each ≤64 chars, first char non-digit (`[A-Za-z_.]`) so URL tails like `python.org/3/library/...` never chain; extension REQUIRED, 2-8 chars, letter-first (rejects `e.g`, `3.16.0`); lookahead `(?![\w/]|\.\w)` makes URL-token rejection backtrack-proof and blocks `docs.python` inside `docs.python.org` while allowing sentence-final `ROADMAP.md.`; all quantifiers bounded (ReDoS discipline, verify.py:271-275). Zero-dir matches allowed (`CHANGELOG.md`) at the documented cost of matching bare domains (`pypi.org`) — declared "phantom-safe" because a phantom anchor touches no commit and is verdict-neutral (verify.py:238-252). Over-match is the cheap direction FOR COMMIT DRIFT ONLY.
- Cap: `_MAX_ANCHOR_CITATIONS = 24` (verify.py:292) — separate from and higher than `_MAX_PATHS_PER_BODY = 8` (verify.py:107) because an anchor is a pathspec string, not a stat.
- Sole consumer: `commit_drift_anchor_paths` (verify.py:1793), over `_bounded_scan_text(body)` (32 KiB cap, verify.py:126, 878-895). It is NOT used by `detect_path_drift`.
- Why relative paths are excluded from existence checking: module docstring verify.py:53-56 ("too many false positives in prose, and without an anchor we'd be checking the cwd at retrieval time which is meaningless"); restated verify.py:232-236 ("a relative path can't be stat'd without knowing its root … For COMMIT drift the root is known — the memory's origin repo"). Enforcement point: `_normalize_candidate` accepts only `~/`, `/` (len≥3, non-placeholder, non-single-segment-routelike), and drive-absolute; everything else hits the final `return None` at verify.py:1194.

New behavior needs a NEW arm name; `PREREGISTRATION.md` is frozen.
2. **The published-results equality pin is exact-dict.** `test_bench_rot.py:235` requires `modes.shipped_default == modes.drift_only_relative_cite` in the COMMITTED JSONs. Any re-published run must keep both arms byte-identical (they differ only in the calendar anchor), and any new per-arm key must appear in both. Note the current arms cannot exercise item (a) at all — `verdict_for` passes no `worktree_root` — so "bench proves the feature" requires editing `verdict_for` (run.py:773), which trips the source-grep pin at `test_bench_rot.py:273-290` if the `commit_drift_count=count if drift_status is not None else None` line is disturbed.
3. **`verdict_from_signals` is signature-pinned to exactly three signals** (`tests/test_verify.py:3199`, inspect-based). Item (b) must be implemented by changing what FEEDS `path_drift_missing`/`commit_drift_count` or the ladder internals — adding a fourth parameter fails the pin, and the pin's own docstring demands new EVIDENCE (the `SHA_MARKER` tombstone, durability.py:197-269) before deletion. Tier wire-strings and `{"never","stale"}` are also pinned (`test_server_v12_features.py:375/671/684`).
4. **`None` vs `0` for `commit_drift_count` is load-bearing in both directions.** Measured `0` demotes a calendar-stale memory to `fresh` (verify.py:2136); `None` keeps it at `spot_check_required` — the branch protecting the ~36% judgement-class bodies (verify.py:2199-2206). Any recut that converts "no anchors"/"couldn't ask" into `0` mass-demotes stale prose memories to fresh. The bench instrument mirrors the distinction (run.py:790-805).
5. **`PathDriftReport.missing` doesn't record provenance.** Anchored-attestation misses (verify.py:731) and prose-extraction misses (verify.py:634) land in the same `missing` tuple, and `has_drift` = `bool(missing)` alone (verify.py:419-435) is the only path-leg input to the verdict. Item (b)'s "escalate only on claim-anchored evidence" therefore needs a new bucket or tag — and the `dropped_as_route` reach-note (verify.py:379-410) documents how a new bucket FAILS to travel: it must be threaded through `MemoryHit` fields (search.py:1850-1856), `hit_to_dict` (`_response.py:159-186`), and three independently-gated emit sites (show.py:146-150, handlers/search.py:993, `_response.py:159-163`), or it is invisible on the wire. The measured evidence for (b) is already in-tree: ~0/15 prose-path alerts real vs 3/3 anchored (verify.py:2207-2214).
6. **Item (a) cannot reuse `_RELATIVE_CITATION_RE` unfiltered for existence checks.** Its over-match tolerance is justified ONLY by phantom-neutrality in commit history (verify.py:238-242): zero-dir matches include bare domains (`pypi.org` — 2-8 letter-first "extension" admits `.org`), and `worktree_root/pypi.org` will stat missing → fabricated drift. Existence checking inverts the cost asymmetry; a route/domain/existence-arbitrated filter layer is mandatory, plus a cap decision (relative citations currently share neither the 8-slot stat cap nor a stat budget — 24 anchors × stat per hit is a new cost class on the hottest path).
7. **Cross-host: item (a) amplifies the existing false-missing gap.** Anchored relative checking against a synced-from-elsewhere `worktree_root` marks EVERY citation missing (no root-liveness check, verify.py:688-731; `_path_exists` folds errors to False, 1491-1500).
